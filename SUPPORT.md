# Support

Functional Acceptance is currently a development preview. Support is best
effort and limited to the latest `main` branch; there is no compatibility or
response-time SLA.

## Where to ask

- Use [GitHub Issues](https://github.com/Quine-rq/functional-acceptance/issues) for reproducible defects, installation problems, documentation corrections, and focused feature proposals.
- Include the installed commit, agent/environment, exact request, non-sensitive evidence, and the expected versus observed user outcome.
- Use [SECURITY.md](SECURITY.md) for security-sensitive reports. Do not put those details in public Issues.

## What maintainers can help with

The project can help clarify documented Skill behavior, reproduce a bounded
local example, and review a focused improvement. It cannot provide access to
third-party services, validate another application's production behavior,
guarantee agent-host compatibility, or operate a user's deployment.

## Before opening an issue

Read the [installation guide](INTEGRATIONS.md), verify the installed copy and
retry only in an isolated project with synthetic data. Preserve failed evidence:
a command that returns success is not enough to establish the user outcome.
