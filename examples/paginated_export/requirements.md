# 分页导出的固定用户要求

用户目标：把提供的本地分页 JSON 中全部记录导出为一个新 CSV，其他程序能读回完全相同的字段；失败不能覆盖用户已有文件。

此样本的输入是已经提供完整分页集合的**合成 fixture**。它验证真实 Python CLI、分页遍历、CSV 编码与实际文件落盘，不验证网络分页请求、远端 API、存储服务、权限或真实业务数据。没有下载或筛选步骤，不把这些能力算进已验证范围。

## 验收要求

1. 输入必须是至多 **2 MiB（2,097,152 字节，包含边界）** 的 UTF-8 普通文件，拒绝源文件本身为符号链接、目录、管道等特殊文件。输入根对象只有 `pages` 数组；每页恰有 `page` 与 `records`，页号从 1 连续递增。每条记录恰有字符串字段 `id,title,notes`，ID 非空且全局唯一。超限、非法或过深嵌套 JSON、模糊的重复键、非法字段或页序必须提供友好非零错误且不生成最终 CSV，不能发布一个看起来成功的部分导出。
2. 默认健康导出必须覆盖全部页面，每条记录恰好出现一次，顺序为页面顺序及页内顺序。`fixtures/pages.json` 的固定真值是 **3 页、5 条记录**，ID 依次为 `r-001,r-002,r-003,r-004,r-005`；最后一页的 `r-005` 不得缺失。
3. CSV 必须是 UTF-8，首行为 `id,title,notes`。使用标准 CSV 读取器读回后，所有字段与 `fixtures/expected_records.json` 完全相同；中文、emoji、逗号、双引号、LF 和 CRLF 都是字段内容的一部分，不能丢失或改写。
4. `pages: []` 或合法的空记录页得到仅有表头的 CSV，返回成功；空集合不是缺少文件。缺少必要产物时不能判断完整性通过。
5. 输出必须使用新路径，父目录需已存在。任何既存文件、目录、符号链接（包括悬空链接）都不得被覆盖；源路径同时作为输出也必须拒绝且保留源文件。
6. 正常可处理的输入/文件错误返回非零退出码、提供错误文字；校验失败不创建最终 CSV。完成文件采用同目录临时文件后排他发布，同名并发只能有一个写入成功。无法排他发布时明确失败，不能降级为覆盖写入。

## 独立期望与缺陷对照

`fixtures/expected_records.json` 是随要求预先冻结的独立期望，测试不导入 exporter 的实现，也不从本次 CSV 计算应有数量或内容。修改 fixture 及期望属于样本要求变更，应一并审查；测试运行不会更新它们。

显式 `--fault omit-final-page` 是受控缺陷注入：对固定多页 fixture 只导出前两页、得到 4 条记录，但命令仍返回 0。这条路径故意违反第 2 项，供同一内容验收识别。不能因为原生测试套件成功检测到该缺陷，就把缺陷导出本身说成业务通过。

固定合成期望与原生测试是公开的功能样本，适合机制核查。它不是对 Agent 隐藏答案的目标提取保留集，也不构成真实项目、其他平台或完整 Skill 的评测结果。
