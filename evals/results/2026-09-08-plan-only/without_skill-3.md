# 分页导出验收方案

本次只制定方案，已静态读取本项目的 `requirements.md`、`README.md`、`export.py`、`test_export.py` 及三个 fixture。未运行 Python、导出、测试或材料工具，未修改项目文件。以下所有执行与验证均为后续计划，不能据此宣称验收通过。

## 用户结果与验收边界

用户要把已经提供完整分页集合的本地 JSON 导出成一个新 CSV：全部记录按原顺序出现一次，其他程序读回字段完全相同，失败时已有文件和输入不被破坏。

验收依据以 `requirements.md` 为准。固定健康输入是 3 页、5 条，ID 顺序为 `r-001,r-002,r-003,r-004,r-005`；独立内容真值为预先冻结的 `fixtures/expected_records.json`。不得从生成的 CSV 反推应有数量或内容，不得为通过检查而修改 fixture 或期望。

这是合成数据下的本地 Python CLI、分页遍历、CSV 编码和文件落盘验收；不覆盖网络请求、远端 API、存储服务、真实业务数据或其他平台。

## 执行前需确认的条件

获得后续执行授权后，先确认 Python 为 3.8+、所用解释器路径、临时目录位置及读写权限，并确认输出所在文件系统支持同目录硬链接。当前机器是否满足这些条件尚未检查；标准库实现不等于运行环境已经可用。

所有验收输出和异常样本都使用本次新建的专属临时目录；项目输入保持只读，输出父目录事先明确存在，每次导出使用独立的新文件名。确认该目录属于本次验收后再做硬链接、符号链接或管道能力检查。文件系统不支持硬链接时，应报告环境不满足健康导出前提；同时核验程序明确失败且不覆盖文件，不能改成覆盖写入来绕过条件。

## CSV 完整性与字段不变的具体口径

先确认预期路径存在实际 CSV，再以 UTF-8 严格解码、使用标准 CSV 读取器读回；文件打开时使用 `newline=""`，保留字段内 LF、CRLF。表头必须恰为 `id,title,notes`，包括顺序，不接受新增、缺失或改名的列。

将读取出的完整记录列表与固定 `expected_records.json` 做顺序敏感的逐记录、逐字段相等比较。这样同时检查记录数量、ID 唯一性、页及页内顺序、末页遗漏和内容变化。辅助显示 5 条及完整 ID 序列以便复核，但数量和 ID 相同不能替代全字段相等。

中文、emoji、逗号、双引号、空字符串、LF 和 CRLF 都按原字段比较，不做 trim、换行统一或其他“清洗”。CSV 内有带换行的字段，禁止用文本行数判断记录数量。退出码 0、文件存在或文件非空都不能单独证明完整性。

## 异常、原文件保护与恢复

静态代码表明：输入全部校验、完整 CSV 编码后才创建输出目录内的 `.export-*.tmp`；写完、flush 和文件 fsync 后，通过 `os.link` 排他发布。已有路径预检查之外，发布动作还承担并发保护；不支持排他发布时没有覆盖写入的降级路径。这是代码依据，尚不是本机执行证据。

后续用本次专属目录内的哨兵文件模拟原文件，保存操作前字节、目录内容、链接目标和目标文件字节。执行后逐项核对：既存文件不变，目录内容不变，链接仍指向原目标，悬空链接仍悬空；源输出同路径时源字节不变。不要用真实用户文件做破坏性故障样本，也不要删除既存文件来让重试成功。

正常可处理的参数、输入和文件错误必须非零退出并有友好错误文字；现有 CLI 约定返回 2。校验失败不得创建最终 CSV；写入、同步或发布失败应无新发布的部分 CSV，已有路径不变，并清理自身临时文件。重试使用新路径；并发失败方不得自行覆盖成功方的结果。

已有测试没有专门证明所有错误分支。后续需补充或安排独立验证：非法 UTF-8 字节、根对象及页对象多余字段、遗漏页字段、跳号或重复页号、嵌套对象重复键，以及临时文件创建、写入、fsync、硬链接发布失败。逐项核对退出码、可读错误、最终路径、原文件字节和本次临时文件，而非只依据测试名宣称全覆盖。补充测试或故障注入需要后续授权，不能在本轮改项目或运行。

强制终止、系统掉电和磁盘故障可能留下临时文件，当前说明没有承诺自动清理或掉电后的持久性。临时文件不作为完整产物；最终 CSV 若存在仍须通过同一内容检查。若发布后清理临时文件失败，不能只凭非零退出码认定最终文件不存在，应先检查状态再决定重试。清理前确认相关进程已结束，逐个核实本次目录内的具体文件；不得扫描删除其他目录，不做递归清空。需要保留的证据先归档，再按明确路径清理。
