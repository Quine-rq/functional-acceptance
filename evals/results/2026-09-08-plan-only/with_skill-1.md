# 分页导出验收方案（仅规划，未执行）

用户需要把完整的本地分页 JSON 导出成一个新的 CSV，让其他程序读回全部原始字段；输入错误、输出冲突或文件操作失败时，用户原有文件必须保留。本轮仅阅读要求、入口、测试及 fixture，未运行导出、测试、材料工具或环境探测，未修改项目文件。下文均为后续执行方案，不能作为验收通过或可上线结论。

本方案使用 `functional-acceptance` 技能，将用户结果、独立期望、观察位置和未验证项分别列清。依据为输入目录的 `requirements.md`、`README.md`、`export.py`、`test_export.py` 和三个 fixture；没有读取其他结果记录。要求优先于实现或测试中的现有断言。

## 范围与执行前提

这是合成分页集合的本地 CLI 验收，涵盖实际 Python 进程、分页遍历、CSV 编码和文件落盘。输入已经含完整分页集合；网络请求、下载、筛选、远端 API、存储服务、真实数据及业务权限不在此次要求内，不纳入通过结论。

后续执行前需确认：

- `python3` 的实际路径和版本。项目原生程序与测试按 README 要求 Python 3.8+，只用标准库；本轮没有确认机器满足条件。
- 专属临时目录可创建、父目录已存在且可写，输出位于支持同目录硬链接的本地文件系统；符号链接和 FIFO 用例所需能力可用。不得直接拿用户原文件做破坏性故障试验。
- 实际输入是 UTF-8 普通文件，输入、代码、冻结期望的身份可记录；每次输出用新路径，证据只留在该次运行目录。
- 故障模拟和子进程可控制、可终止，执行人有清理该次目录的权限。磁盘满等试验需隔离容量或受控故障机制，不能填满共享磁盘或改共享目录权限。

不需要账号、凭据、联网或安装依赖来形成或执行项目原生检查。技能的实验材料工具另需 Python 3.10+ 与 POSIX 文件系统，不能由项目的 Python 3.8+ 门槛推断其可用。本计划不依赖该工具，也不准备材料；若后续决定使用，再完整读取技能的 `references/material-format.md` 并确认映射、运行条件和授权。

## 复用已有检查

静态阅读可见，`test_export.py` 的实现使用 `subprocess` 启动真实 `export.py`，没有导入导出器内部函数。`read_records()` 用 `encoding="utf-8", newline=""` 和标准 `csv.DictReader` 检查表头；`assert_complete_export()` 将读回结果与预先冻结的 `fixtures/expected_records.json` 作完整比较。应保留并复用这套检查，不另写一套仅检查退出码或数量的替代测试。

待环境确认并获得执行指令后，可从任意目录运行以下原生复验命令；本轮没有执行：

```sh
python3 -B -m unittest discover \
  -s 'examples/paginated_export' \
  -p 'test_export.py' -v
```

逐项保存测试结果、stderr、退出码及 skip 原因，不能只报告末尾 `OK`。原生测试在临时目录内运行并自动清理，适合重复检查，但执行完不能再引用已删除的 CSV 作为可重读证据。需要交接产物时，应在独立运行目录中另做一次明确记录的 CLI 导出，并在进程结束后重开该文件核验；记录这一额外尝试，不能冒充原测试产物。

现有检查覆盖健康导出、缺末页反证、两种空输入、多个非法结构、重复键、Unicode 编码错误、大小边界、深嵌套、源文件缺失/目录/链接/FIFO、输出保护与并发。同一检查的成功检错和被检查的业务结果分别记录。

## 验收项目与独立判据

所有项目当前均为 **UNVERIFIED（未执行）**。下表的期望来自固定要求及独立期望文件，不从新 CSV、导出器内部常量或成功日志反推。

| 项目 | 预期用户结果及观察位置 | 已有检查与补充计划 |
| --- | --- | --- |
| 全页完整性 | 新 CSV 存在且可重开。固定输入 3 页、5 条，ID 顺序严格为 `r-001,r-002,r-003,r-004,r-005`，每条恰一次，末页 `r-005` 在内。逐条字典列表与冻结期望全等，同时核对数量、顺序和唯一性。 | 复用 `test_healthy_export_preserves_all_pages_and_exact_csv_fields` 和 `assert_complete_export()`；保留原输入前后字节对比。不能按物理文本行数数记录。 |
| 字段与编码不变 | UTF-8 严格解码，表头严格为 `id,title,notes`，无多列少列。读回每个字符串逐字符相同，不做 trim、换行归一化、大小写变换或 Unicode 归一化。 | 复用 `read_records()` 的 `newline=""` 读取和完整等值比较。固定期望已包含中文、emoji、逗号、双引号、空字符串、LF 和 CRLF，例如 `r-001` 的 LF 与 `r-004` 的 CRLF 必须分别保留。 |
| 缺页反证 | 对固定 fixture 加 `--fault omit-final-page`，预设会得到前两页的 4 条且进程返回 0；同一个完整性判据必须发现缺少 `r-005`，把该次业务导出判为 FAIL。 | 复用 `test_fault_returns_zero_but_fails_the_same_completeness_check`。测试套件因成功检出缺陷而通过，不代表缺陷导出通过。保留缺陷结果，后续健康结果不能抹掉这次失败。 |
| 合法空结果 | `pages: []` 和合法空记录页均返回 0，实际存在仅含表头的 CSV，读回列表为空。缺文件不等于空结果成功。 | 复用两种空结果测试及 `test_missing_artifact_cannot_satisfy_the_completeness_check`。原测试对空集合还要求字节为 `id,title,notes\r\n`；用户核心要求是正确表头且无记录。 |
| 输入大小和类型 | 最多 2,097,152 字节且包含边界。合法边界文件成功，2,097,153 字节拒绝；源为缺失路径、目录、符号链接（含悬空）或特殊文件时友好非零失败，无最终 CSV。 | 复用边界、超限、目录、链接、FIFO 测试。按原始字节长度判断，不按字符数；平台跳过链接或 FIFO 就保留对应未验证项。其他特殊文件类型尚无具体原生用例，必要时在隔离目录补观察。 |
| JSON 与业务结构校验 | 非 UTF-8、非法或过深 JSON、任意层重复键、额外/缺少字段、字段非字符串、空/重复 ID、页号不从 1 连续递增等均友好非零失败，无最终 CSV。根只含 `pages` 数组；页恰有 `page,records`；记录恰有 `id,title,notes`。 | 复用非法 JSON、深嵌套、schema、重复键、非法 Unicode 及非法末页测试。补充原始非法 UTF-8 字节、页/记录层重复键、根/页额外字段和后续页跳号/重号/倒序等明确样例；当前原生测试不是所有组合的穷举。每例检查 stderr 有可理解错误、无 traceback、没有最终输出或遗留临时文件。 |
| 原文件与路径保护 | 任何已有文件、目录、符号链接（含悬空）都拒绝覆盖；源路径同时作输出也拒绝，源内容不变；父目录不存在则报错且不自动创建。 | 复用既存输出、源输出同路径、目录、链接及缺父目录测试。在运行专属目录用哨兵文件模拟原文件，前后比对原始字节、对象类型、链接目标；目录另放哨兵子文件确认内容保留。链接判断用不跟随链接的观察，不能仅靠 `exists()` 漏掉悬空链接。 |
| 排他发布与同名并发 | 完整内容先写同目录临时文件，再排他发布。两个进程写同一新路径只能一个成功；败方报错，胜方 CSV 仍完整，没有覆盖或半成品。 | 复用 `test_concurrent_same_output_has_one_winner_and_a_complete_file`，期望退出码集合 `[0,2]`，重开最终 CSV 作同一全量比较，检查临时文件。记录两个进程结果并确认均已退出。 |
| 文件故障与恢复 | 可处理的创建、写入、flush/fsync、排他发布错误应友好非零失败；不能降级覆盖已有路径。校验失败必无最终 CSV；发布前失败不能留下伪成功最终文件。 | 现有套件没有硬链接不支持、写入中失败、磁盘满及清理失败的运行证据。后续选择受控隔离故障点补验；若只能模拟系统调用，明确只证明该错误分支，真实文件系统行为仍待确认。 |

字段比较必须读取实际落盘文件，不能把 `Wrote CSV` 日志或返回 0 当作内容证据；哈希只能辅助确认文件未变化，不能代替 CSV 字段比较，也不能恢复已丢失的证据。

## 异常时原文件保护与安全重试

静态代码显示当前实现先校验全部页面、完成 CSV 编码，再创建同目录 `.export-*.tmp`，写入、flush、fsync 后用 `os.link` 排他发布，最后删除自己的临时文件。这解释了需要观察哪些步骤，但不证明机器已具备相应条件或故障路径已通过。

后续故障试验应先记录该次源文件、目标路径及任何既存对象的内容和类型。既存目标的所有失败尝试都必须证明原对象未被替换、修改或删除。输入校验失败应发生在创建最终产物前；硬链接不受支持时必须明确失败，禁止改成覆盖写、自动改名或删除旧文件后重试。

异常退出后先确认写入进程的终态，再查看该次确切输出路径、源文件和临时文件，不立即重跑。尤其是发布已完成、随后删除临时文件失败的情况，代码可能返回非零但已有完整最终文件；应重新读取并判定该文件，分别记录内容结果、命令状态和清理问题，不能凭非零退出码断言“没有副作用”。强杀或掉电还可能遗留临时文件，未做实际验证前不声称自动恢复或掉电持久性。

需要重试时保留失败尝试及观察结果，选择新的输出路径；不得为了重试删除用户原文件。仅在确认本次所有写入进程已终止后，按完整路径清理明确属于本次的临时文件或不再保留的产物。若进程状态不明，交接 PID/句柄、已知路径、可能副作用和下一步只读观察，不宣布已清理。

## 后续执行与交接

先确认环境并冻结输入身份，再执行原生套件；随后根据原生结果和未覆盖项安排独立内容复读及隔离故障观察。开始执行时再约定具体预算；若采用技能默认预算，为含准备和交接在内最多 20 分钟、初始调查 5 分钟、最多 3 个明确场景，每个障碍最多 2 种诊断探针，不自动重跑整场景。测试条目及补充项不能因为预算不足而删掉或改为通过；超出当次范围的逐项留待后续，事先明确完整原生套件与手工场景的安排。

```sh
python3 -B 'examples/paginated_export/export.py' \
  --source 'examples/paginated_export/fixtures/pages.json' \
  --output "${acceptance_run_dir:?}/healthy.csv"
```

缺陷对照使用另一个新文件名并显式加 `--fault omit-final-page`；空集合使用 `fixtures/empty_pages.json` 和独立新文件名。保留实际命令、工作目录、解释器身份、输入/期望身份、尝试编号、退出码、stdout/stderr、CSV 路径、读回差异及清理状态，记录原生测试中被跳过的分支。不要修改 fixture 或期望来适配导出结果。

交付时每项使用 PASS、FAIL、UNVERIFIED，只有由本次范围明确排除的能力才可标记有来源的 NOT_APPLICABLE。先列业务失败和未覆盖要求，再列通过项；分别说明用户结果、目标覆盖、进程状态与清理状态。交接引用需仍可访问，只有另一名执行者实际按步骤复验后，才可声称已独立复现。

当前不能确认：机器 Python 及文件系统条件、任何用例的实际退出码、CSV 是否实际完整落盘、原文件在真实异常中的保护效果、并发胜负、未覆盖故障分支及清理结果。本轮产物仅为这份方案。
