# 分页导出验收方案

本轮仅制定方案。已只读检查本项目的 `requirements.md`、`README.md`、`export.py`、`test_export.py` 和三个 fixture；未运行 Python、导出、测试或材料工具，未修改项目文件。以下“通过条件”均为后续执行标准，不是已有测试结果。

## 目标与验收边界

用户要把已提供的全部分页记录导出为一个新 CSV，使其他程序读回完全相同的字段；输入非法或文件操作失败时，已有文件必须受到保护。

目标真相以 `requirements.md` 为准。当前代码与测试提供了可复用的实现和检查入口，但静态阅读不能证明运行机器能够成功执行。样本只涉及完整提供的本地合成分页 JSON、真实 Python CLI、CSV 编码和文件落盘；不包含下载、筛选、网络分页、远端 API、账号权限、存储服务或真实业务数据。

本次不改变字段、页序、记录顺序、空结果语义、新路径要求及禁止覆盖规则。成功必须同时有正确的进程结果和可读取、内容正确的最终 CSV，不能仅凭退出码或成功提示判断。

执行时使用独立、由本次验收拥有的临时目录，提前创建父目录，每次导出使用新的文件名；异常场景使用自建样本或源文件副本。不要拿用户已有文件直接制造覆盖、磁盘故障或权限故障。涉及符号链接、FIFO 或故障注入时，先确认环境能够安全支持；不能执行的项目明确记为“未验证”，不记为通过。

## 怎样确认 CSV 完整且字段没有变化

健康 fixture 的固定真值为 3 页、5 条记录，ID 顺序必须为 `r-001,r-002,r-003,r-004,r-005`。核对 CSV 读回后的完整记录列表与 `expected_records.json` 完全相等：同时确认条数、全局唯一性、顺序、末页 `r-005` 存在，以及每条记录恰有 `id,title,notes` 三个字符串字段。CSV 本身不含页号，因此以已知分页输入和最终记录序列验证页遍历结果。

CSV 必须能按 UTF-8 严格解码，首行字段顺序为 `id,title,notes`。使用标准 CSV 读取器，不按文件行数计记录，不自行用逗号切分。读取时保留原始换行，不做 trim、Unicode 归一化或 LF/CRLF 转换；逐字段确认中文、emoji、逗号、双引号、空字符串及字段内 LF、CRLF 均与冻结期望一致。

空集合或空记录页的成功结果仍须有实际 CSV 和表头；文件不存在、不可读、只有成功提示都不能算空结果通过。健康、空结果和故意漏页三种结果分别判定：整套 unittest 通过代表漏页反证有效，故意漏页的那份 CSV 仍是业务验收失败。

## 输入与异常补充项

后续如需证明全部要求，应在独立验收目录补充下列场景；本轮不创建样本或脚本，不修改原生测试：

- 用合法 UTF-8 JSON 验证恰好 2,097,152 字节可接受，2,097,153 字节拒绝；已有测试可直接覆盖。计量按实际字节，不能按字符数。
- 已有结构测试包含代表性错误，进一步覆盖根对象/页面额外字段、页号跳号或重复、页号非整数、同页重复 ID、页面或记录内重复 JSON 键，以及原始非法 UTF-8 字节。错误必须非零、有友好文字、不发布最终 CSV；按当前 CLI 约定通常为退出 2，不能以 traceback 代替用户错误提示。
- 在可控环境补充读取失败、输出目录不可写、临时文件写入或同步失败、硬链接不支持等情况。现有原生套件没有直接验证这些故障，不能由正常导出或并发用例推定已通过。无法安全复现时记录未验证原因，不在用户数据目录制造故障。

## 异常时怎样保护原文件

从代码可见，程序先校验全部输入并完成 CSV 编码，再在输出同一目录创建 `.export-*.tmp`，写入、刷新并同步后使用 `os.link` 排他发布。输出预检查涵盖悬空链接；最终链接操作处理预检查后发生的同名竞争。不能只验预检查，也不能在硬链接失败时降级为覆盖写入。

后续验收按以下结果检查保护是否成立：

1. 运行前记录自建源文件、既存输出和链接目标的原始字节与对象状态；运行后核对保持不变。源输出同路径必须拒绝，已有目录和链接本身必须保留，悬空链接不能被新文件替换。
2. 输入校验或发布前文件错误必须非零、错误可见，且没有最终 CSV；正常可处理的错误还应清理本次临时文件。父目录不存在时不能自动创建它。
3. 同名并发只能一个成功；另一个失败且不得损坏已发布的完整 CSV。重复执行命中同一路径应拒绝，恢复时使用新路径，不覆盖已有产物。
4. 若异常发生在发布后清理阶段，须检查实际最终文件和临时文件状态，不能仅凭非零退出推断“从未发布”。未核实的文件不得当作成功结果，也不要自动覆盖重试。
5. 强制终止、掉电或磁盘故障可能残留本次 `.export-*.tmp`。将其视为临时文件，不作为最终 CSV。恢复后先核查最终产物；清理只针对本次拥有、已确认完整路径的文件，不递归清空目录，也不删除源文件或用户旧文件。本方案不宣称系统崩溃后的持久性已获验证。
