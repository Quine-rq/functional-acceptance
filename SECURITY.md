# Security policy

Functional Acceptance is an installable development preview. The only version
receiving security fixes is the latest commit on `main`; no release branch or
response-time SLA is offered.

## Report a vulnerability

Do **not** publish exploit details, credentials, private reports, or proof-of-
concept payloads in a public issue.

1. Open this repository's [Security tab](https://github.com/Quine-rq/functional-acceptance/security) and choose **Report a vulnerability**. Private vulnerability reporting is enabled for this repository.
2. If that GitHub control is ever unavailable, open a public issue titled **Security contact requested** with no vulnerability details. A maintainer will arrange a private channel before technical details are shared.

Please include the affected commit or installation method, impact, a minimal
safe reproduction, and any mitigation you already know. Do not include real
customer data, access tokens, or credentials.

## Scope

Report vulnerabilities in this repository's shipped Skill, helper, examples,
documentation installation guidance, or CI configuration. Product bugs in a
project being checked by the Skill belong to that project's maintainers.

## Disclosure and updates

We will acknowledge a valid report when maintainers are available, assess its
scope, and coordinate a fix or mitigation before public disclosure where
practical. This is a best-effort policy, not a service-level commitment.
